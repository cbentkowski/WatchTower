# WatchTower 0.10.0

Relay adds policy-driven notification scheduling, routing, escalation, and delivery history.

## Highlights

- Create persisted notification policies using severity, known exploitation, application criticality, environment, exposure, workspace, owner, finding state, and finding age conditions.
- Preview matching findings and recipient routes before saving a policy.
- Deliver notifications immediately or through daily, weekly, and adaptive schedules with configurable delivery windows and reminder intervals.
- Route notifications to workspace owners and selected additional owners, with optional delayed escalation contacts.
- Review notification attempts in a dedicated rotating log with human-readable workspace, application, policy, recipient, SMTP outcome, and message details.
- Audit policy additions, edits, and removals with readable field-level configuration changes.
- Preserve existing notification acknowledgements, restart-safe deduplication, lifecycle alerts, and migration-compatible defaults.

## Configuration

Notification policies are stored in `config/notification-policies.json`. Existing installations receive default policies equivalent to the previous High, Critical, and known-exploited notification behavior.

Review the notification policy and delivery-history sections of the user guide before customizing the defaults.
